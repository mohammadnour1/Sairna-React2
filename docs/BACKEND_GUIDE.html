    أساسيات الباك لمطوّر فرونت

    هاد الحد الأدنى اللي لازم تعرفه لتقرا باقي الدليل. إذا بتعرفه، فوت عالفصل الجاي.

    شو هو طلب HTTP؟

    كل مرة الموقع بدو بيانات، بيبعت رسالة للسيرفر فيها 4 أجزاء:

    POST /api/v1/website/auth/login          ← 1. الـ method + 2. الـ URL (المسار)
Content-Type: application/json           ← 3. الـ headers (معلومات إضافية)
Authorization: Bearer eyJhbGciOi...         (هاد header الـ token، بس للطلبات المحمية)

{ "email": "a@b.com", "password": "12345678" }   ← 4. الـ body (البيانات المبعوتة، بالـ POST/PATCH بس)

    والسيرفر بيرد برسالة فيها status code (رقم بيقلك نجح ولا لأ) و body (عادةً JSON).

    الـ Methods

    Methodمعناهبيغيّر بيانات؟مثال من سيرنا
    GETجيب لي شيلأ، آمن تجرّبه قد ما بدكGET /cities
    POSTاعمل شي جديد / نفّذ عمليةإيPOST /bookings (حجز جديد)
    PATCHعدّل جزء من شي موجودإيPATCH /trips/5 (لوحة الإدارة بس)
    DELETEاحذفإيDELETE /companies/3 (بسيرنا هو أرشفة، مش حذف)
    انتبه: السيرفر مشترك وحقيقي. الـ GET ما بيضر، بس أي POST/PATCH/DELETE بيكتب بيانات حقيقية. حجز تجريبي بياخد مقعد فعلي لحتى تلغيه، وما في endpoint بيمحي شي نهائياً.

    شو هو JWT؟

    لما تسجّل دخول، السيرفر بيعطيك نص طويل اسمه token (من نوع JWT). هاد متل بطاقة دخول: بتحطه بكل طلب محمي بالـ header Authorization: Bearer <token>، والسيرفر بيعرف مين إنت من خلاله. السيرفر ما بيحفظ "جلسة"، الـ token نفسه هو الإثبات.

    • الـ token بسيرنا صالح 7 أيام. بعدها السيرفر بيرد بـ 401.
    • ما في endpoint لتجديده (refresh) ولا لتسجيل الخروج. "تسجيل الخروج" عنّا = نمحي الـ token من المتصفح.
    • الـ token مش سر مشفّر ضدك، بس هو مفتاح حسابك: ما بينطبع بالـ console وما بينحط بالكود.

    شو هو CORS؟ وليش في proxy؟

    المتصفح، لأسباب أمان، بيمنع صفحة على localhost:5173 تقرا رد من دومين تاني، إلا إذا السيرفر قال صراحةً "مسموح" بـ header اسمه Access-Control-Allow-Origin. هاد اسمه CORS.

    سيرفر سيرنا بيرد بـ Access-Control-Allow-Origin: * (يعني مسموح للكل). بس احتياطاً، وقت التطوير منبعت الطلبات لنفس الدومين تبع Vite، و Vite بيوصّلها هو للسيرفر. هيك المتصفح ما بيشوف أي طلب "cross-origin" أصلاً. التفاصيل بـ فصل العنوان والـ proxy.

    الـ axios client والـ interceptors

    src/api/client.js هو الباب الوحيد اللي بيطلع منه أي طلب لموقع المسافرين. 31 سطر، وكل سطر إلو سبب.

    import axios from 'axios'
import { clearToken, getToken } from '@/utils/storage'
import { authEvents } from './authEvents'
import { AUTH_FORM_PATHS } from './endpoints'

export const client = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL,   // من ملف الـ env
  timeout: 15000,                                 // إذا السيرفر ما رد بـ 15 ثانية → خطأ
})

// (A) قبل ما يطلع أي طلب: حط الـ token إذا موجود
client.interceptors.request.use((config) => {
  const token = getToken()
  if (token) config.headers.Authorization = `Bearer ${token}`
  return config
})

// (B) بعد ما يرجع الرد: إذا 401 والطلب كان فيه token → الجلسة انتهت
client.interceptors.response.use(
  (response) => response,
  (error) => {
    const status = error.response?.status
    const url = error.config?.url ?? ''
    const hadToken = Boolean(error.config?.headers?.Authorization)
    if (status === 401 && hadToken && !AUTH_FORM_PATHS.includes(url)) {
      clearToken()
      authEvents.emit('unauthorized')
    }
    return Promise.reject(error)   // الخطأ بيكمّل لعند React Query
  },
)

    شو هو الـ interceptor؟

    دالة بتمرق عليها كل الطلبات (أو كل الردود) قبل ما توصل لوجهتها. بدل ما تكتب headers: { Authorization } بـ 13 مكان، بتكتبها مرة وحدة هون.

    ليش الشروط الثلاثة بالـ 401؟

    الشرطليش
    status === 401السيرفر ما قبل الـ token
    hadTokenإذا الطلب أصلاً ما كان فيه token، ما في جلسة لننهيها
    !AUTH_FORM_PATHS.includes(url)401 من /auth/login معناه "كلمة السر غلط"، مش "انتهت الجلسة". هاد بيتعرض كخطأ بالفورم بس

    ليش authEvents وما منستعمل React مباشرة؟

    client.js ملف JavaScript عادي، مش component، فما فيه يستعمل hooks ولا navigate. فبيبعت "إشارة" عن طريق event emitter صغير (src/api/authEvents.js، 13 سطر)، و AuthContext (اللي هو React) عم يسمع لهالإشارة وبيتصرّف: بيمحي بيانات المستخدم من الـ cache وبيعرض toast انتهت الجلسة، سجّل دخولك من جديد.

    // src/api/authEvents.js — الفكرة كلها
authEvents.on('unauthorized', handler)   // AuthContext بيشترك
authEvents.emit('unauthorized')          // client.js بيبعت

    وين بينحفظ الـ token؟ (src/utils/storage.js)

    الحالةوينبيضل لإيمتى
    Login مع "تذكرني"localStorage، المفتاح sairna-tokenلحتى يخلص الـ token (7 أيام) أو تسجيل خروج
    Login بدون "تذكرني"sessionStorageلحتى تسكّر التاب
    RegisterlocalStorage (كأنو "تذكرني")متل الأول

    getToken() بيدوّر بالـ sessionStorage أول، بعدين بالـ localStorage. و clearToken() بيمحي من الاتنين. كل القراءة والكتابة جوّا try/catch لأن الـ storage ممكن يرمي خطأ بالـ private mode.

    شو ما منحفظ: كلمة السر أبداً، ولا كائن المستخدم. المستخدم دايماً بيجي من GET /auth/me. الـ token لحاله هو اللي بينحفظ.

    الـ Services

    Service = دالة async عادية. بتبعت طلب واحد، وبترجّع بيانات "نظيفة". ما فيها React، ولا state، ولا toast.

    // src/services/bookings.service.js
export async function getMyBookings() {
  const { data } = await client.get(endpoints.myBookings())  // GET /bookings/me (الـ token بيتحط تلقائياً)
  return mapBookings(data)                                    // خام ← Booking[]
}

export async function cancelBooking(id) {
  const { data } = await client.post(endpoints.cancelBooking(id))  // POST بدون body
  return { id: Number(data?.id ?? id), status: data?.status ?? 'CANCELLED' }
}

    شو بيعمل الـ service زيادة على الطلب؟

    • بيحضّر الـ body: مثلاً login بيعمل email.trim().toLowerCase() قبل ما يبعت، و createBooking بيحوّل كل الأرقام لـ Number وبيعمل trim للأسماء والأرقام.
    • بيقرّر شو يبعت: getTrips عن قصد ما بيبعت companyId حتى لو المستخدم اختار شركة. منجيب كل رحلات الخط ومنفلتر بالمتصفح، لحتى نقدر نعرض عدد الرحلات لكل شركة بالفلاتر.
    • بيمرّق الرد على mapper: ما في service بيرجّع data الخام.

    شو ما بيعمل؟

    • ما بيمسك الأخطاء (try/catch). الخطأ بيطلع لفوق لعند React Query، واللي بيعرضه هو الـ hook أو الـ component.
    • ما بيعرض رسائل، وما بيعمل navigate.
    ليش هالفصل بين الطبقات؟ لأنك فيك تستدعي getMyBookings() من أي مكان (hook، test، سكربت) وبتاخد نفس النتيجة. والـ service سهل تقراه: كل دالة 3–5 أسطر.

    الـ Mappers: ترجمة رد السيرفر

    الـ mapper دالة "نقية" (pure function): بتاخد الـ JSON الخام وبترجّع object بالشكل اللي الواجهة بدها ياه. هو المكان الوحيد بالمشروع اللي بيعرف أسماء حقول الباك.

    ليش ما منستعمل الرد كما هو؟

    1. الباك بيتغيّر. إذا بكرا صار اسم الحقل departure_time بدل departureAt، بتعدّل سطر واحد بالـ mapper بدل 20 component.
    2. الرد مو جاهز للعرض. الأوقات بـ UTC، المدة مش موجودة، الشركة ما إلها لون…
    3. الحقول ممكن تكون ناقصة أو null. الـ mapper بيتحمّل هالشي وبيعطي قيمة واضحة (null) بدل ما الواجهة تنكسر.

    الـ Mutations: لما نكتب على السيرفر

    تسجيل الدخول والجلسة

    هون بتجتمع كل القطع: الـ token، الـ interceptor، /auth/me، الـ context، وحماية الصفحات.

    تسجيل الدخول خطوة خطوة

    1. LoginForm.jsx: المستخدم بيكبس دخول. useAuthForm بيعمل validation محلي أول (إيميل صحيح، كلمة سر 8 أحرف). إذا في غلط، ما في طلب.
    2. useLogin() بيستدعي login({ email, password }) من auth.service.
    3. الطلب: POST /auth/login ← الرد: 
      { "accessToken": "eyJ...", "tokenType": "Bearer", "portal": "website",
  "user": { "id": 31, "name": "…", "email": "…", "role": "USER" } }
    4. mapAuthResponse بيحوّله لـ { token, user }.
    5. onSuccess ← signIn(session, { remember }) بـ AuthContext:
      • setToken(token, remember) ← localStorage أو sessionStorage.
      • queryClient.setQueryData(['auth','me'], user) ← منحط المستخدم بالـ cache فوراً، فما في داعي لطلب /auth/me هلّق.
      • setTokenState(token) ← الـ context بيتحدّث، والـ header بيعرض اسم المستخدم.
    6. toast أهلاً وسهلاً! تم تسجيل الدخول. وانتقال لـ state.from (الصفحة اللي بعتتك للدخول) أو /account.

    لما ترجع تفتح الموقع (استرجاع الجلسة)

    1. AuthProvider بيقرا الـ token من الـ storage: useState(getToken).
    2. إذا موجود ← useMe(true) بيبعت GET /auth/me، والـ interceptor بيحط الـ token.
    3. وقت الانتظار: status = 'loading' ← ProtectedRoute بيعرض spinner عم نتحقق من حسابك...
    4. نجح ← status = 'authenticated'. رجع 401 ← الـ interceptor بيمحي الـ token ← status = 'guest' ← تحويل لـ /login. ما في نت ← status = 'error' مع زر "حاول مرة ثانية".

    كيف getErrorMessage بيقرّر

    1. ما في رد (ما في نت أو timeout)؟ ← تعذّر الاتصال بالخادم. تأكد من الإنترنت وحاول مرة ثانية.
    2. message كود معروف (EMAIL_TAKEN…)؟ ← ترجمته من CODE_MESSAGES.
    3. message array تبع validation؟ ← أول كلمة بكل رسالة هي اسم الحقل ("seats.0.passengerPhone must match…")، فمنترجمها من FIELD_MESSAGES.
    4. ولا شي؟ ← الـ fallback اللي بعتّه.

    DELETE مش حذف

    unwrap()

    الـ mappers بالإدارة (admin/api/mappers/admin.mappers.js) بتقبل الرد كـ array مباشرة أو جوّا { data: … }. احتياط إذا الباك غيّر الشكل.

    تبويب Network بالـ DevTools

    1. F12 ← تبويب Network ← فلتر Fetch/XHR.
