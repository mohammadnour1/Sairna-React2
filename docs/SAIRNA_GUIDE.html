    03

    كيف بتمشي البيانات (Architecture)

    أهم فكرة بالمشروع: كل طبقة إلها شغلة وحدة، وما في طبقة بتنط فوق التانية.

    القواعد الذهبية

    1. الـ Components ما بتستدعي axios

    بتستعمل hooks بس. هيك بتقدر تغيّر طريقة الجلب بدون ما تلمس الواجهة.

    2. الـ Services دوال async عادية

    بدون React. بتطلب من الـ client وبترجّع بيانات mapped.

    3. الـ Mappers هني الوحيدين اللي بيعرفوا أسماء الحقول الخام

    إذا تغيّر الـ backend (مثلاً departureAt صار departure_time)، بيتغيّر ملف واحد.

    4. الـ Pages رفيعة

    بتقرا الـ route params وبتركّب الأقسام. تقريباً بدون منطق.

    مثال كامل: من الضغطة للشاشة

    1. المستخدم بيكبس «ابحث عن رحلات» بـ SearchForm ← بتستدعي search(values) من useTripSearch.
    2. search بتتحقق بـ validateSearch وبتنقل لـ /results?originId=2&destinationId=1&date=…&people=1.
    3. ResultsPage بتقرا الـ URL عن طريق useResultsParams (وبتصلّح أي قيمة غلط).
    4. useTrips(criteria) ← getTrips() بـ trips.service.js ← client.get('/trips', { params }).
    5. الرد الخام بيمرّ على mapTrips: التوقيت بيتحوّل لتوقيت دمشق، المدة بتنحسب، المسافة التقريبية بتنحسب.
    6. useTripFilters بيفلتر ويرتّب على الجهاز (client-side) وبيحسب عدد الرحلات لكل شركة.
    7. TripList بيعرض TripCard لكل رحلة، أو skeleton وقت التحميل، أو empty state.
    الكود: service + mapper للرحلات 
    // src/services/trips.service.js
export async function getTrips({ originId, destinationId, date }) {
  const { data } = await client.get(endpoints.trips(), { params: { originId, destinationId, date } })
  return mapTrips(data)
}

// src/api/mappers/trip.mapper.js (مختصر)
export function mapTrip(raw) {
  const departure = toDamascusDateTime(raw.departureAt)   // '07:00Z' → '10:00'
  const durationMinutes = minutesBetween(raw.departureAt, raw.arrivalAt)
  return {
    id: Number(raw.id), origin: mapCity(raw.origin), company: mapCompany(raw.company),
    date: departure.date, departureTime: departure.time, durationMinutes,
    price: Number(raw.price), availableSeats: raw.availableSeats,
    estimatedKm: estimateRoadKm(origin, destination),   // الـ API ما فيه مسافة
  }
}

    طبقة HTTP و React Query

    الـ axios client

    ملف src/api/client.js بيعمل instance واحد إلو interceptor-ين:

    export const client = axios.create({ baseURL: import.meta.env.VITE_API_BASE_URL, timeout: 15000 })

// 1) قبل كل طلب: حط الـ token إذا موجود
client.interceptors.request.use((config) => {
  const token = getToken()
  if (token) config.headers.Authorization = `Bearer ${token}`
  return config
})

// 2) بعد كل رد: 401 برّا صفحات الدخول = الجلسة انتهت
client.interceptors.response.use((r) => r, (error) => {
  if (error.response?.status === 401 && hadToken && !AUTH_FORM_PATHS.includes(url)) {
    clearToken()
    authEvents.emit('unauthorized')   // AuthContext بيسمع وبينهي الجلسة، والصفحات المحمية بتحوّل لـ /login
  }
  return Promise.reject(error)
})
    ليش event emitter؟ الـ client ملف JavaScript عادي، ما فيه React، فما فيه يستعمل useNavigate. فبيبعت «إشارة» (authEvents)، والـ AuthProvider (اللي جوّا React) بيسمعها وبيتصرّف.

    الـ proxy وقت التطوير

    بالتطوير، VITE_API_BASE_URL=/api/v1/website، و Vite بيحوّل أي طلب لـ /api للسيرفر الحقيقي. هيك المتصفح بيشوف كل شي من نفس الـ origin وما في مشاكل CORS. بالإنتاج منستعمل العنوان الكامل (السيرفر بيبعت Access-Control-Allow-Origin: *).

    React Query: الإعدادات العامة

    staleTime: 60_000            // البيانات بتعتبر "طازة" لدقيقة
refetchOnWindowFocus: false  // ما في إعادة جلب كل ما ترجع عالتاب
retry: ما في إعادة لأخطاء 4xx، ومحاولة وحدة إضافية لأخطاء الشبكة

    الـ Query keys

    كل بيانات بالـ cache إلها مفتاح. المفاتيح كلها بـ src/api/queryKeys.js:

    cities:     ['cities']
trips:      ['trips', { originId, destinationId, date }]
trip:       ['trips', 'detail', id]
tripSeats:  ['trips', 'detail', id, 'seats']   ← بيبلّش بـ trip(id)، فإبطال trip بيبطل المقاعد كمان
me:         ['auth', 'me']
myBookings: ['bookings', 'me']
booking:    ['bookings', 'detail', id]
    💡 ليش هالترتيب مهم؟ invalidateQueries({ queryKey: ['trips'] }) بيبطل كل شي بيبلّش بـ 'trips': القوائم، تفاصيل الرحلة، والمقاعد. هيك بعد الحجز بيتحدّث كل شي بسطر واحد.

    وين بتعيش الحالة (State)؟

    سؤال أساسي بأي تطبيق React. القاعدة: حط كل معلومة بالمكان اللي بيناسب «عمرها» ومين بيحتاجها.

    المعلومةالمكانليش
    بيانات السيرفر (رحلات، حجوزات…)React Query cachecache، تحميل، أخطاء، إعادة جلب — كله جاهز
    معايير البحث + الفلاترالـ URL (search params)الرابط بينشارك، الـ refresh ما بيضيّع شي، زر الرجوع بيشتغل
    مدخلات الفورم قبل الإرسالuseState بـ SearchFormمحلية ومؤقتة
    آخر بحثsessionStorage (sairna-last-search)لتعبئة فورم الرئيسية وزر «الرحلات»
    خطوات الحجز (المقاعد + المسافرين)useReducer + مسودة بـ sessionStorageما بتضيع إذا رجعت خطوة، أو عملت refresh، أو رحت تسجّل دخول
    الثيمThemeContext + localStorageبيلزم بكل الصفحات وبيبقى بعد الإغلاق
    الجلسةAuthContext (token + useMe)المستخدم دايماً من السيرفر، مش من التخزين
    الرسائل (toasts)ToastContextأي مكان بيقدر يبعت رسالة
    القائمة، النوافذ، إظهار كلمة السرuseState محليما حدا تاني بيحتاجها
    تقدّم المحاكاةuseTrackingSimulationمنطق خاص بصفحة وحدة

    Lazy loading

    كل صفحة بـ React.lazy(() => import('@/pages/X'))، فبتصير chunk لحالها وبتنحمّل أول ما تزورها. الـ Suspense بـ MainLayout بيعرض spinner بالانتظار. MapLibre (1 ميغا) كمان بـ chunk لحالها وبتنحمّل بـ import() بس لما يظهر map.

    الـ Scroll

    ScrollManager بيرجع لفوق بس لما يتغيّر الـ path. تغيير الفلاتر (الـ search params) ما بيحرّك الصفحة — متل render(true) بالمرجع.

    تسجيل الدخول والجلسة

    «تذكرني» (B14)

    • مأشّر عليها ← الـ token بـ localStorage (بيبقى بعد إغلاق المتصفح).
    • مش مأشّر ← بـ sessionStorage (بيروح مع إغلاق التاب).
    • القراءة: sessionStorage أول، بعدين localStorage. والخروج بيمسح الاتنين.
    • التسجيل الجديد دايماً «متذكّر».

    حالات الجلسة (status)

    statusمتىProtectedRoute بيعرض
    guestما في tokenتحويل لـ /login مع state.from
    loadingفي token و /auth/me لسا عم ينطلبSpinner «عم نتحقق من حسابك...»
    authenticated/auth/me رجّع مستخدمالصفحة
    error/auth/me فشل لسبب غير 401 (شبكة)رسالة + «حاول مرة ثانية»

    فورم الدخول والتسجيل: useAuthForm

    hook مشترك بين الفورمين: بيحفظ القيم، بيتحقق محلياً (validateAuth)، بيحوّل أخطاء السيرفر لأخطاء تحت الحقول، وبيعمل focus لأول حقل غلط. الحقول مربوطة بـ aria-invalid و aria-describedby.

    ⚠ مهم: كلمة السر ما بتنحفظ بأي مكان، والمستخدم ما بيتخزّن كمصدر حقيقة. بس الـ token.

    إمكانية الوصول (Accessibility)

    • كل عنصر تفاعلي بينوصل بالكيبورد مع حلقة focus واضحة (3px solid #4cc8bf).
    • كل حقل إلو <label>، والأخطاء مربوطة بـ aria-describedby و aria-invalid.
    • المقاعد: aria-label="مقعد N"، aria-pressed، و disabled للمحجوز.
    • الأزرار اللي فيها أيقونة بس عندها aria-label عربي.
    • الـ Modal: role="dialog"، aria-modal، focus trap، رجوع الـ focus للزر اللي فتحها.
    • الـ toasts بـ role="status" و role="alert" للأخطاء.
    • رابط «تخطّى إلى المحتوى» أول عنصر بالصفحة.
    • احترام prefers-reduced-motion (الأنيميشن بتوقف والمحاكاة بتبلّش موقّفة).
    • الصور إلها alt عربي، والزخرفية alt="".

    🧹 تنظيف بيانات الاختبار

    انعمل حساب تجريبي واحد وحجزين تجريبيين، والحجزين انلغوا. الحساب لسا موجود لأن الـ API ما فيه endpoint لحذف حساب.

    جرّب بنفسك — checklist

    1. افتح الرئيسية، غيّر الثيم، وتأكد إنو الخيار بيبقى بعد الـ refresh.
    2. اختار حلب ← حلب وابحث: لازم تطلع رسالة خطأ.
    3. ابحث حلب ← دمشق بتاريخ قريب، جرّب الفلاتر، ولاحظ إنو الـ URL بيتغيّر والصفحة ما بتطلع لفوق.
    4. افتح رابط فيه تاريخ قديم (date=2020-01-01): لازم يتصلّح مع toast.
    5. اختار رحلة، مقعدين، عبّي المسافرين، ارجع خطوة وتأكد إنو الأسماء لسا موجودة.
    6. أكّد كضيف ← سجّل دخول ← لازم ترجع لخطوة المراجعة.
    7. أكّد الحجز، افتح «حجوزاتي»، افتح التذكرة بالكيبورد (Tab + Enter)، سكّرها بـ Esc.
    8. افتح «تتبّع الرحلة»، وقّف الحركة، غيّر الثيم (الخريطة ما لازم تتأثر)، واستنى لـ 100%.
    9. ألغِ الحجز، وتأكد إنو زر التتبّع اختفى.
    10. افتح /أي-شي: لازم تطلع صفحة 404.

    قاموس المصطلحات

    المصطلحالمعنى ببساطة
    Componentدالة بترجّع جزء من الواجهة (JSX). متل قطعة Lego.
    Propsالمدخلات اللي بتعطيها للـ component من برّا.
    Stateبيانات بتتغيّر مع الوقت، ولما تتغيّر React بيعيد عرض الـ component.
    Hookدالة بتبلّش بـ use وبتستعمل ميزات React (state، effects…). بتجمع منطق قابل لإعادة الاستعمال.
    Effectكود بيشتغل بعد العرض لمزامنة شي برّا React (خريطة، timer، تخزين).
    Contextطريقة لمشاركة قيمة مع كل الـ components تحت بدون تمريرها بالـ props.
    Reducerدالة (state, action) => newState. كل التغييرات بمكان واحد وبأسماء واضحة.
    Queryطلب قراءة بيانات من السيرفر (GET) بإدارة React Query.
    Mutationطلب بيغيّر بيانات بالسيرفر (POST) — دخول، حجز، إلغاء.
    Invalidateتعليم بيانات بالـ cache إنها قديمة كي تنجلب من جديد.
    Interceptorكود بيمرّ عليه كل طلب أو رد بـ axios.
    Mapperدالة بتحوّل الرد الخام من السيرفر لشكل داخلي ثابت.
    JWT / Token«بطاقة دخول» من السيرفر بتنبعت مع كل طلب محمي.
    Lazy loadingتحميل كود صفحة أو مكتبة بس لما تلزم.
    Fallbackبديل بيظهر لما الشي الأساسي يفشل.
    RTLRight-to-left: اتجاه الكتابة العربي.
    Proxyوسيط بـ dev server بيحوّل طلبات /api للسيرفر الحقيقي.
